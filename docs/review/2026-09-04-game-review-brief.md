# The Baker Corporation — 게임 리뷰 브리프 (2026-09-04)

전제: 이 문서는 이종 리뷰어(codex)가 **게임 자체**를 여섯 축으로 건설적으로 비평하기 위한 현황 정리다. 보안은 리뷰 범위에서 제외한다. 리뷰어는 이 저장소를 읽을 수 있으므로, 문서의 주장과 코드가 어긋나면 코드를 믿고 그 어긋남을 지적하라.

## 0. 고정 제약 (리뷰어가 뒤집을 수 없는 것)

- 마감: WebMCP Challenge 제출 **2026-09-04 17:00 KST**(1:00 am PT). 지금부터 남은 시간은 반나절이다. 제안은 "마감 전 2시간 안에 되는 것 / 제출 후 v1.1 / 장기"로 나눠라.
- 확정된 설계 결정: 사람=홈즈(화면 클릭), 에이전트=왓슨(ChatGPT가 페이지 도구 10개 호출) / 페이지가 진실을 쥐고 판정하며 `lie`·`truth`·`provedBy`는 어떤 응답에도 나가지 않는다 / **기소는 사람만, 2회** / 시간 페널티 없음(걸린 시간만 회고에 표시) / 이동 무료·대화·조사·기록검색만 배 시간 소모 / 한국어 UI는 한국어만 표시(영·한 저장) / SVG 금지, three.js 허용 / 첫 플레이어는 튜토리얼 강제 선형 / 소멸 증거(장갑·발자국)는 유지 / 힌트 사다리 대신 "준비 신호"(`docs/research/05-stuck-synthesis.md`) / 라이선스 코드 AGPL-3.0 + 콘텐츠 CC BY-NC-ND.
- 실행 환경: ChatGPT 내장 브라우저(Chrome 152). 에이전트는 채팅 입력으로만 행동하고 픽셀을 읽는다. 턴당 13~15초. WebGL·Web Audio는 첫 제스처 후 동작 확인됨.

## 1. 개요

- 장르: 탐정 TRPG. "살아있는 세계 + 하나의 진실". 사실은 결정론(커널), 경로는 창발(플레이어·왓슨), 말은 생성(ChatGPT가 커널 카드만으로 NPC 연기).
- 시리즈 "The Baker Corporation". 배경 SF 화물선 *Marlow*. Ep0 "Titan, I Perceive"(튜토리얼, 도난), Ep1 "The Sensor in the Night"(살인).
- 코드: Vite 8 + React 19 + TS + zustand 5, vitest 150 tests, 60 파일 4,385 LOC. 커밋 82. 프로덕션 https://baker-corporation.vercel.app (`?bridge=1` 테스트 다리).
- 문서: 스펙 `docs/superpowers/specs/2026-09-03-baker-corporation-design.md`, 리서치 `docs/research/00~05*.md`.

## 2. 코어 루프 & 메카닉

**현재**
- 루프: 방 이동(무료) → 인물 초상 클릭 → 화제 칩(`talk`) 또는 자유 질문(`ask`, 키워드 매칭) → 물증 마커 클릭(`examine`, 3D 클로즈업) → 왓슨이 `timeline`/`cross_check`/`search_records`로 대조·검색 → 왓슨이 `submit_theory`(예비 심리: 주장별 proven/unsupported/contradicted) → 사람이 **기소**(누가·어떻게·결정적 물증) → 판결·회고.
- 커널 `src/kernel/`: `invoke(ep, state, actor, cmd)` 순수 함수. 카드(수첩)가 유일한 공유 상태. `redact.ts`가 진실 필드 제거. `accuse`는 도구로 등록되지 않음.
- 시계: `COST = { talk 5, ask 5, examine 5, timeline 10, cross_check 20, search_records 30 }`. 승무원은 명부(`presence`)대로 시각에 따라 방을 옮기고, 티커에 "◆ 린드: 기관실 → 주방"으로 알린다.
- 막힘 설계(오늘 추가): `leads.ts` — 인물별 안 들은 화제 수·대조 여부, 방별 미방문·미조사·미청취 개수(내용 없음). 증명 가능한 명제의 75%가 수첩에 갖춰지면 왓슨이 "더 가져올 것 없음, 나머지는 조사관 몫" 한 줄. 기소 실패는 "세 부분 중 N개 어긋남"만.

**의도** — 왓슨은 홈즈의 판단을 대체하지 않는다. 사람이 결정하고 왓슨은 가져온다. 생성형 에이전트가 붙은 게임의 새 문법: 말은 매 판 다르고 사실은 같다.

**알려진 약점 / 질문**
- `ask`의 자유 질문은 키워드 매칭이라 "모른다"가 잦다. 대체 설계가 있는가(의도 분류를 왓슨에게 맡기고 커널은 topic만 받기 등)?
- 왓슨의 `submit_theory`는 주장 단위로 판정을 돌려준다. 오브라 딘식 묶음 확정(3개 단위)이 더 나은가, 아니면 튜토리얼 교육 장치로 지금이 맞는가?
- 사람이 직접 하는 행동과 왓슨에게 시키는 행동의 경계가 플레이어에게 명확한가? (플레이테스트: 채팅만으로 1시간 진행한 뒤 기소 버튼 존재를 몰랐다.)
- 두 번의 기소가 주는 긴장과, 커버리지 신호가 주는 안도의 균형.

## 3. 시스템 기획 & 밸런싱

**현재**
- 콘텐츠 규모: Ep0 방 4·인물 3·진술 8(거짓 5)·물증 4·기록 3·명제 4·튜토리얼 10단계. Ep1 방 9·인물 5·화제 14·진술 70(거짓 9)·물증 10·기록 15·명제 10·수법 3.
- 규칙 검증기 `validate.ts` R1~R7(참조 무결성, 거짓말 ≥3인, 반박 가능성, 결정적 물증 도달 가능, 골든 패스 완주 등). `scripts/check-ep0.ts`, `check-ep1.ts`가 골든 패스를 실제로 돌린다. R7(완전 탐색 비용 ≥ 1.6×예산)은 마감 폐지 후 정보성.
- 시간 창: 진술 `availableFrom`(린드의 거짓말은 200분 후 주방에서만), 물증 `availableTo`(발자국 180분, 장갑 240분에 소멸 — 둘 다 대체 경로 있음).
- 명제 → `provedBy` 세트(복수 경로), `refutedBy`. 진실 = 범인·수법·결정적 물증 3칸.

**알려진 약점 / 질문**
- 시간 페널티가 사라진 뒤 `COST`의 의미는 "회고 숫자"뿐이다. 비용표를 유지할 가치가 있는가, 아니면 리듬 장치로 재해석해야 하는가?
- 거짓말 9/70. 진술의 대부분이 참이라 대조의 밀도가 낮을 수 있다. 적정 비율은?
- 결정적 물증이 하나뿐(재킷). 대체 결정 물증 없이 "그 카드를 못 본 플레이어"는 구조적으로 실패한다. 허용 가능한가?
- 수법 3개 중 2개는 미끼(에어록·약물). 미끼의 근거 밀도가 충분한가?

## 4. 사용자 경험 & 인터페이스

**알려진 약점 / 질문**
- 플레이테스터 피드백: "챕터 서사가 인지되기 어렵고 등장인물 인지도 어렵다"(인트로·서류로 대응했으나 재검증 안 됨), "키비주얼 없는 UI"(Direction A 프레임으로 대응).
- 채팅만 쓰는 플레이어와 화면만 쓰는 플레이어 사이의 정보 비대칭(수첩은 공유되지만 왓슨은 화면의 버튼을 모른다).
- 화제 칩이 14개 중 4개만 보이는 접기 규칙이 탐색을 막는가?
- 모바일 폭은 사실상 미지원.

## 5. 아트 스타일 & 시각적 정체성

- 8.2MB 아트를 lazy 없이 싣는다.
- 키비주얼(홈 히어로) 한 장이 시리즈 정체성을 감당하는가?

## 6. 기술적 안정성 & 최적화

**현재**
- 번들: index 348KB(gzip 116KB), three 708KB(gzip 183KB, lazy import), build 316KB. 첫 페인트부터 WebMCP 등록(`useWebmcp.ts`), `navigator.modelContext`/`document.modelContext` 양쪽 대응, Origin Trial 토큰(만료 2026-11-17).
- 상태: zustand + localStorage(`persist.ts`), 재접속 시 `hydrate`. 테스트 150개(jsdom, 커널·도구·UI·오디오·리드).
- 자동 검증: Playwright + `?bridge=1` 다리(`window.__baker.start/call/tools`)로 골든 패스·클로즈업 13개·오디오·커버리지 실측.
- 알려진 함정: Node 25 localStorage 스텁(테스트 셋업으로 우회), 코덱스 이미지 생성 시 stdin 미닫음 행.

**알려진 약점 / 질문**
- 에러 경계 없음. 도구 호출 실패 시 사용자에게 보이는 표면이 토스트뿐.
- 다중 탭·동시 세션(사람 화면 + ChatGPT 내장 브라우저가 별개 탭)에서 localStorage 상태가 갈라진다. 이건 설계상 "한 탭에서만 플레이"인데 명시되지 않았다.
- three.js 초기화 실패 감지·폴백 전환 기준이 `hasWebGL()` 한 번뿐.
- 저사양·모바일 성능 미측정.

## 8. 리뷰 요청

여섯 축 각각에 대해 (a) 가장 잘 된 것 1개, (b) 가장 약한 것 1~2개와 그 근거(코드·문서 위치), (c) 개선안을 "마감 전 2시간 / v1.1 / 장기"로 분류해서 써라. 우선순위 총 10개 이내로 압축한 요약을 맨 앞에 두라. 보안·비밀값·권한 관련 지적은 제외한다. 칭찬은 근거가 있을 때만, 비판은 대안과 함께.
