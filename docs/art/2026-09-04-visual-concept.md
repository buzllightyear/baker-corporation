# The Baker Corporation — 비주얼 컨셉 & 아트 바이블 초안 (2026-09-04)

전제: 마감과 무관하게 계획한다. 게임 화면·키비주얼·영상이 한 바이블 위에 선다. 참조는 사용자가 만든 키비주얼 4장(스페이스 오페라 × 아케인 영향)과 넷플릭스 《아케인》. 게임 설계 결정(사람=홈즈 1인칭, 왓슨=로봇, 제목 The Baker Corporation, 배경 화물선 말로우, 두 에피소드)은 유지한다.

## 1. 컨셉 문장

> **낡은 회사, 넓은 우주.** 베이커 사는 여러 세계에 지부를 둔 조사 회사다. 지부마다 낡은 로봇 왓슨이 한 대씩 있고, 조사관(당신)은 세계를 옮겨 다닌다. 시리즈의 하늘은 스페이스 오페라(첨탑 도시, 행성 궤도, 함대)이고, 각 사건의 바닥은 손때 묻은 작은 공간(말로우의 주방, 기관실)이다. 큰 하늘과 작은 방의 대비가 비주얼의 축이다.

이 문장은 세 가지를 해결한다. 참조 이미지의 스케일(스페이스 오페라)과 현재 콘텐츠(화물선)를 한 세계 안에 놓고, "멀티버스" 아이디어를 시리즈 구조로 흡수하며, 키비주얼(시리즈)과 방 그림(에피소드)의 역할을 나눈다.

## 3. 아케인에서 가져오는 것 / 안 가져오는 것

**가져온다**
- **색상 인코딩**: 세계·진영·상태마다 색을 배정하고 어기지 않는다 (§4).
- **구도의 기하학**: 대각선, 실루엣 대 광원, 화면 밖으로 나가는 큰 곡선(행성 궤도·고리), 주체는 3분할 교점.
- **하이브리드 질감**: 단단한 형태(하드 서피스) 위에 붓자국이 보이는 2D 텍스처. 사진 같은 렌더 금지, 완전한 셀 애니 금지. 림 라이트로 형태를 자른다.
- **인물 시트 규율**: 인물마다 정면·측면·후면·표정 6종·핵심 소지품(참조 3번 형식). 초상과 영상이 같은 얼굴을 쓴다.

**안 가져온다**
- 특정 캐릭터 디자인(징크스·바이·제이스). 실루엣과 의상 실루엣도 피한다.
- 필트오버 아르데코 양식 그대로. 우리 건축은 §5의 자체 규칙을 따른다.

## 5. 건축·소품 규칙 (스페이스 오페라 층)

- 첨탑은 수직, 항구는 수평, 궤도는 곡선. 세 기하가 한 프레임에 같이 있으면 "베이커 사의 세계"로 읽힌다.
- 도시 표면은 금속이 아니라 **석재+유리**. 말로우(금속·녹)와 대비된다.
- 베이커 사 지부는 어느 세계에서든 같은 간판(로고 마크·금선)으로 알아본다. 회사의 항상성이 시리즈의 정체성.
- 소품: 왓슨의 유지보수 로그 단말, 봉인 테이프, 화물 장부 — 사건마다 "손에 드는 물건" 3개를 정하고 키비주얼·UI·영상에 반복.

## 6. 인물 시트 (7장)

**홈즈**, **왓슨**, 밴스 선장, 오카포 선의, 린드 기관사, 사토 항해사, 레예스 요리사 (7장). 각 시트: 정면·측면·후면, 표정 6, 핵심 소지품 3, 색 팔레트 6칸, 키워드 8. 생성 앵커는 `docs/art/prompts-v2.md`.

왓슨 시트가 가장 중요하다. 지금의 왓슨 초상(낡은 청록 로봇, 호박 눈)을 기준으로 전신·관절·마모를 정한다. 눈 하나가 왓슨의 아이콘이 된다(UI의 왓슨 표시·티커·음악 모티프와 연결).

## 7. 키비주얼 샷 리스트

1. **시리즈 키아트**: 첨탑 도시의 항구, 홈즈(코트, 얼굴 보임)와 그 옆 한 걸음 앞에 왓슨. 하늘에 행성 궤도. 금선 로고. (참조 4번 + 왓슨)
2. **에피소드 1 키아트**: 화물칸 3의 봉인 테이프 앞, 보라 조명, 왓슨의 호박 눈만 빛남.
3. **에피소드 0 키아트**: 의무실 금고 문이 열린 채, 흰 녹색.
4. **홈 히어로**: 1번의 와이드 크롭. 현재 hero-ship.jpg 교체.
5. **승무원 단체**: 시트 기반 5인 + 왓슨. 현재 crew-photo.jpg 교체.

## 8. UI 언어 (참조 1번 기준)

- 패널: 검은 유리(blur 12px, 알파 .55), 1px 금선, 모서리 직각, 안쪽 여백 넉넉히. 리벳·스텐실·경고 줄무늬 없음.
- 위계: 제목은 세리프 디스플레이(라틴 Cormorant Garamond 계열, 한글 Noto Serif KR 또는 고운바탕), 본문 산세리프(Noto Sans KR), 데이터·시각·ID는 모노. 자간 넓게, 대문자 소제목.
- 색: 금선은 홈즈(사람)의 층, 청록선은 왓슨의 층. 티커·왓슨 상태·왓슨 토큰은 청록, 기소·판결·수첩은 금.
- 구조: 참조 1번의 "조사 → 가설 → 추리 → 결과" 4단계를 상단에 얇게 표시. 우리 루프와 1:1 (조사=대화·물증, 가설=예비 심리, 추리=대조·시간표, 결과=기소).
- 실 뭉치 추리판: 리서치(03-interaction-patterns) 후보였던 것을 이 UI 언어로 만든다. 카드 사이 얇은 금선.
- 문 이동·초상·물증 마커: 얇은 금선 원과 작은 라벨. 그림을 가리지 않는다.

## 9. 파이프라인 (아케인의 하이브리드를 웹으로 번역)

| 아케인 | 우리 |
|---|---|
| 3D 모델 | 생성 스틸(형태·원근이 단단한 프롬프트) |
| 손으로 그린 텍스처 투사 | 스틸 자체가 붓자국을 가짐 + 깊이 맵으로 시차(현행 `StageArt3D`) |
| 카메라 무브 | 전경·중경·배경 3층 분리(매팅) → 2.5D 시차 + 미세 애니메이션(지나가는 함선, 깜빡이는 등) |
| 컬러 스크립트 | §4 표. 방마다 LUT 1개 |
| 인물 일관성 | §6 시트를 모든 생성의 참조 이미지로 |

도구: 이미지는 codex/ChatGPT 생성(현행), 깊이는 Depth-Anything-V2(현행 `scripts/depth-maps.py`), 층 분리는 rembg 또는 SAM 계열, 영상은 같은 층을 Remotion 또는 After Effects에서 카메라 무브. 실제 3D 모델링은 하지 않는다.

## 10. 영상과의 연결

- 트레일러는 §7의 1·2번 샷을 카메라 무브로 잇고, 게임 화면은 §8의 UI로 녹화한다. 키비주얼과 게임 화면이 같은 색 대본을 쓰므로 편집에서 이질감이 없다.
- 왓슨의 눈 → 게임 UI의 왓슨 토큰 → 음악 모티프(두 음)를 영상의 3초 시그니처로 통일.

**규율**
- 생성은 항상 P2의 사전을 통해서만 한다. 프롬프트를 즉석에서 쓰지 않는다 — 앵커가 깨지면 인물이 갈린다.
- 승인된 자산은 `concept/`에 남기고, 프로덕션 자산은 그것을 참조해 만든다. 컨셉은 지워지지 않는다.
- 한 단계에서 반려가 나오면 그 자산만 재생성한다. 전체 재생성은 스타일 블록이 바뀔 때만.
- 미적 판단은 디렉터 전속. 에이전트는 일관성(얼굴·색·구도 규칙)만 검수한다.
